## Project Summary

WalletEditor Registry v2 program: Phase 1 sync library, Phase 2 pre-run gate at worker execution start. Phase 3 migrates **hold/Отлёжка runtime readers** to PostgreSQL with I-MAN-11 fail-closed guard.

---

## Task Goal (Phase 3 only)

After gate sync, runtime readers use PG — not Dropbox — for `hold`/`Отлёжка`. Only ManualSync reads manual sheets from Dropbox.

```text
Dropbox (hold/Отлёжка) → ManualSync → PG → readers
```

---

## Critical Invariants

| ID | Rule |
|----|------|
| I-MAN-08 | Only ManualSync reads manual sheets from Dropbox |
| I-MAN-10 | No mid-run Dropbox re-read in postgres readers mode |
| I-MAN-11 | PG readers only after ≥1 successful manual sync; else fail-closed + health DEGRADED |
| I-MAN-01 | Last-good PG preserved on sync failure |
| I-MAN-06 | No Dropbox registry write removal |
| I-MAN-09 | No legacy sheet cleanup |

### I-MAN-11 fail-closed matrix (`MANUAL_READERS_SOURCE=postgres`, no successful sync)

| Surface | Outcome |
|---------|---------|
| Hold enforcement | `HoldPairsSnapshot.unavailable` → add_partner blocked |
| Auto-enable planning | `RuntimeError` / plan error report |
| Lifecycle refresh | `PERMANENT` outcome |
| `/registry_health` | `degraded=True`, line `DEGRADED: no successful manual sync` |

Successful sync statuses: `success`, `skipped_hash`, `skipped_rev` with `last_manual_snapshot_hash` + `last_manual_sync_at`.
