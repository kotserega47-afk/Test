## Коротко о главном

### _Никакие изменения руками не далаем_

**Все изменения правил выполняются через Telegram-бот**

- Если правило нужно “изменить” — бот сам выключит старое и включит новое

- enabled — технический флаг, пользователь с ним не работает

### Какие правила можно менять

_Оператор управляет только операционными правилами:_

а) Лимиты wallet  
б) Дневной лимит суммы (daily_max_amount)  
в) по партнёру или группе  
г) Пороги анализаторов  
д) conversion / wallet  
е) метрики из разрешённого списка

####   Временные исключения

_интервалы, которые не нужно учитывать в расчётах_

Как менять лимит wallet
Что делает команда

ищет текущий активный лимит

выключает его

добавляет новый

сохраняет историю

Пример
/limit set partner="HH (А-мобайл Сбер + Выплаты)" value=5000000
reason="увеличили лимит по просьбе бизнеса"

Что важно помнить

лимит всегда один активный

“добавить поверх” нельзя — только заменить

старый лимит не удаляется, а архивируется

Как менять порог (threshold)
Что делает команда

находит активный порог по ключу

выключает его

добавляет новый

Пример
/threshold set analyzer=conversion
partner="HH (А-мобайл Сбер + Выплаты)"
metric=conversion_rate
value=8
reason="временное снижение"

Допустимые метрики (v1)

conversion_rate

api_cancel_threshold

wallet_threshold

Если нужной метрики нет — обращаемся к Maintainer, не придумываем сами.

Как добавить временное исключение
Когда использовать

техработы

сбои API

ручная проверка

нерепрезентативные окна

Пример
/exclude add analyzer=conversion
partner="HH (А-мобайл Сбер + Выплаты)"
from="17.01.2026 10:00"
to="17.01.2026 12:00"
reason="техработы партнёра"

Важно

интервалы применяются по OR-логике

если событие попало в интервал — оно исключается

даты должны быть корректны (from < to)

Как выключить или включить исключение

Если исключение больше не нужно:

/exclude off id=EXC-0042


Вернуть обратно:

/exclude on id=EXC-0042

Что происходит при ошибке

Бот ничего не сохранит, если:

найдено больше одного активного правила

некорректная дата или число

нет прав на операцию

файл правил повреждён

В ответе будет указано что именно сломано.

Чего делать нельзя

❌ Редактировать rules.xlsx напрямую
❌ Добавлять второе активное правило “на всякий случай”
❌ Менять YAML-конфиги анализаторов
❌ Придумывать новые метрики без согласования

Если нужно что-то нестандартное

новая метрика

новый тип лимита

изменение логики применения

👉 Обращаемся к Maintainer / Owner.
Это изменение контракта, а не операционное действие.

Главное правило

Если не уверен — не правь Excel.
Если бот не даёт применить — значит правило нарушает контракт.
